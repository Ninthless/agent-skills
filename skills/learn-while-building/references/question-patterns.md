# Question Patterns

Use one pattern at a time and tailor it to the repository's actual behavior.

## Prediction

- “在不看实现的情况下，你预测这个输入会得到什么结果？为什么？”
- “如果依赖返回空值，当前流程会在哪一步结束？”
- “这个请求成功后，哪一个状态会被改变？”

## Tracing

- “从入口开始，依次追踪这个值经过了哪些模块。”
- “这条错误信息是在什么位置产生的？它经过了哪些边界？”
- “如果执行到这一步，当前状态、下一步动作和最终输出分别是什么？”

## Explain-Back

- “用自己的话说明这个模块负责什么，以及它明确不负责什么。”
- “为什么这个规则应该由当前模块拥有，而不是由调用方重复实现？”
- “这个测试保护的是用户可观察行为还是内部实现细节？”

## Transfer

- “如果把当前外部服务替换成另一个提供商，哪些部分应该保持不变？”
- “如果请求可能重复到达，当前设计需要增加什么保证？”
- “如果未来增加第二种存储方式，哪个契约应该保持稳定？”

## Debugging

- “根据现有症状，你的第一个假设是什么？哪条证据可以证伪它？”
- “你认为应该先检查输入、状态转换、依赖返回值还是清理逻辑？为什么？”
- “这个修复解决的是根因，还是只让当前测试通过？”

## Micro-Change

- “如果要支持一个相邻的小需求，你会先修改哪个 owner？为什么？”
- “请指出最小的测试变化，证明这个新分支不会破坏原行为。”
