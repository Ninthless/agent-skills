Frontend route: /users/new

TypeScript request type:
type CreateUserRequest = {
  email: string;
  displayName?: string;
};

TypeScript response type:
type User = {
  id: string;
  email: string;
  displayName: string | null;
  createdAt: string;
};

Client call:
POST /api/users
Content-Type: application/json
Authorization: Bearer <token>

The form requires email, accepts an optional display name, and treats HTTP 201 as success.

The UI handles these error payloads:
HTTP 409
{
  "error": {
    "code": "EMAIL_ALREADY_EXISTS",
    "message": "A user with this email already exists"
  }
}

HTTP 422
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed",
    "fields": {
      "email": "Enter a valid email address"
    }
  }
}

The frontend does not define email length limits, displayName length limits, server-generated ID format, or timestamp format. Those decisions block a fully specified backend contract and must remain local TBD fields rather than invented constraints.
